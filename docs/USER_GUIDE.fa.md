# راهنمای استفاده DevOrchestra — فارسی

نسخه اولیه 0.1.x | قابل اجرا روی Windows، Linux و macOS

DevOrchestra یک رابط گرافیکی محلی برای Codex CLI است. برنامه با Go اجرا می‌شود، صفحه آن در مرورگر پیش‌فرض باز می‌شود و اطلاعات پروژه و تاریخچه درخواست‌ها را در SQLite نگه می‌دارد.

> این نسخه هنوز پنجره Native مستقل، چند Agent همزمان، گردآوری خودکار پرامپت از وب و تکمیل Prompt با مدل AI ندارد.

## ۱. نصب

1. به [GitHub Actions](https://github.com/jahangard/DevOrchestra/actions) بروید و یک اجرای موفق Build and test را انتخاب کنید.
2. از بخش Artifacts بسته سیستم‌عامل خود را دریافت کنید: ویندوز (DevOrchestra-Setup.exe)، لینوکس (deb)، یا مک Apple Silicon (pkg).
3. بسته را نصب و DevOrchestra را اجرا کنید. رابط در مرورگر باز می‌شود.

**توجه:** بسته‌ها هنوز امضای دیجیتال یا تأیید Apple Notarization ندارند و نصب روی دستگاه واقعی باید جداگانه آزمایش شود.

### اجرا از سورس

به Go 1.23 یا جدیدتر نیاز دارید:

    git clone https://github.com/jahangard/DevOrchestra.git
    cd DevOrchestra
    git switch feat/codex-desktop-mvp
    go mod tidy
    go run ./cmd/devorchestra

برای توقف برنامه، فرایند را ببندید یا در ترمینال Ctrl+C بزنید.

## ۲. آماده‌سازی Codex CLI

از منوی **تنظیمات**، وضعیت Codex CLI، Node.js و npm را بررسی کنید.

- در صورت نصب بودن Node.js و npm، دکمه **نصب Codex CLI با npm** را بزنید و نصب را تأیید کنید.
- Installer ویندوز هم گزینه نصب اختیاری Codex را دارد؛ برای آن نیز npm باید قبلاً نصب شده باشد.
- روش دستی:

    npm install -g @openai/codex
    codex login

ورود به حساب را با دستور codex login در ترمینال انجام دهید. DevOrchestra رمز حساب یا توکن ورود را دریافت و ذخیره نمی‌کند. سپس در تنظیمات دکمه **بازخوانی** را بزنید.

## ۳. ثبت پروژه

1. وارد صفحه **پروژه‌ها** شوید.
2. نام و مسیر مطلق یک پوشه *موجود* را وارد کنید؛ برای مثال D:\dev\TavanHub یا /home/user/project.
3. روی **افزودن** کلیک کنید.
4. از داشبورد، پروژه را انتخاب کنید.

برنامه پوشه پروژه را ایجاد نمی‌کند.

## ۴. اجرای پرامپت

1. در **داشبورد**، پروژه مقصد را انتخاب کنید.
2. سطح دسترسی را تعیین کنید: **read-only** برای تحلیل بدون اجازه تغییر فایل‌ها (پیش‌فرض)، یا **workspace-write** برای مجوز ویرایش در محدوده پروژه.
3. درخواست را با جزئیات بنویسید. برای افزودن الگوی «زمینه / معیار پذیرش / تست‌ها»، دکمه **تکمیل ساختاریافته** را بزنید؛ این قابلیت الگوی محلی است و یک فراخوانی جداگانه به مدل هوش مصنوعی ندارد.
4. با دکمه **اجرای Codex** کار را آغاز کنید. نتیجه و رویدادها در بخش خروجی نمایش داده می‌شوند. دکمه **توقف اجرا** برای لغو وجود دارد.

این نسخه تنها **یک اجرای همزمان** دارد. پیش از صدور مجوز ویرایش، بهتر است تغییرات قبلی را Git Commit کنید.

نمونه درخواست:

    ابتدا AGENTS.md و ساختار پروژه را بررسی کن.
    خطای فیلتر جدول مشتریان را بازتولید کن.
    فقط فایل‌های مرتبط را اصلاح و تست رگرسیون اضافه کن.
    فایل‌های تغییر یافته و نتایج تست را گزارش بده.

## ۵. تاریخچه و گزارش‌ها

از منوی **تاریخچه اجرا** آخرین درخواست‌ها را ببینید. با **نمایش نتیجه** رویدادهای اجرا در داشبورد ظاهر می‌شوند. خروجی JSONL، خطاها و وضعیت درخواست در SQLite نگهداری می‌شود. مسیر پایگاه داده در **تنظیمات → SQLite** دیده می‌شود.

**حریم خصوصی:** درخواست‌ها و گزارش‌ها ممکن است شامل کد اختصاصی، اطلاعات حساس یا مسیر فایل باشند. فایل دیتابیس را بدون بازبینی به اشتراک نگذارید. در این نسخه حذف خودکار لاگ‌ها و رمزگذاری درون‌برنامه‌ای دیتابیس پیاده‌سازی نشده است.

## ۶. کتابخانه پرامپت

- از **کتابخانه پرامپت**، الگوی رفع خطا، بررسی کد، توسعه قابلیت، تست یا امنیت را انتخاب و روی **استفاده** کلیک کنید.
- در داشبورد با **ذخیره پرامپت**، دستورهای دلخواه را نگهداری کنید.
- برای وارد کردن پرامپت از GitHub، لینک مستقیم فایل md یا txt از دامنه raw.githubusercontent.com را وارد و **دریافت** را انتخاب کنید.

محتوای بیرونی **قابل اعتماد فرض نمی‌شود** و خودکار اجرا نخواهد شد. قبل از استفاده منبع و دستورها را بررسی کنید. جست‌وجو و گردآوری خودکار از سایت‌های مختلف جزو این نسخه نیست.

## ۷. زبان برنامه

با دکمه **English / فارسی** در نوار بالای صفحه، زبان رابط و راهنمای داخلی عوض می‌شود؛ فارسی RTL و انگلیسی LTR است. انتخاب زبان در مرورگر حفظ می‌شود.
